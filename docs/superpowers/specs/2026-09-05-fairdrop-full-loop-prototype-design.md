# FairDrop 完整闭环原型设计

## 目标

把现有 CoDropPass 单轮交易页扩展为适合黑客松路演的 FairDrop 产品原型：用户可以浏览活动、理解条件报名、查看订单状态；项目方可以查看成交与结算；真实钱包与合约交易继续可用，本地模拟数据用于无钱包演示。

## 结构

- 首屏：FairDrop 品牌、当前网络、钱包连接、活动主数据与明确的“报名/查看活动”入口。
- 用户视图：活动列表、当前活动详情、条件报名表单、订单状态和资金路径。
- 项方视图：成交额、托管余额、成功率、退款率、99%/1% 分账与提款入口。
- 演示态：使用固定活动和订单数据渲染完整状态，不依赖 RPC；连接钱包并配置合约后，现有真实链上读写仍作为主要操作路径。

## 交互与状态

- 通过顶部视图切换在“活动市场 / 我的订单 / 项目方工作台”之间切换。
- 活动市场的活动卡点击后更新当前活动详情，报名表默认加载该活动的价格和场次。
- 报名表支持同行钱包地址、场次偏好和整组成交选项；真实购买仍调用现有 `buy` 合约方法，演示态提交则生成本地订单并展示成功状态。
- 我的订单展示待分配、已获得 Pass、可退款三类状态，并提供 MonadVision 交易入口或模拟操作反馈。
- 项方工作台展示成功成交额与托管总额的区分，避免把托管余额误认为收入。

## 视觉方向

沿用现有蓝橙双色印刷风格，加入更紧凑的工作台导航、细线分隔、状态标签和活动进度条。首屏信号从单一营销 Hero 调整为“正在进行的活动 + 可执行报名”，突出真实产品。

## 边界

- 不新增依赖，不改变 Solidity 合约 ABI。
- 不伪造链上余额；模拟数据只在未连接钱包或未加载合约时展示，并在界面上标注 Demo Mode。
- 多场次和整组规则在 UI 中作为产品概念展示，当前合约购买仍按接收地址数量和固定单价执行。

## 验收

- `npm run build` 通过。
- 桌面与移动宽度无横向溢出，顶部视图切换、活动选择、模拟报名、订单筛选均可操作。
- 连接钱包后，真实合约购买、刷新、提款和交易状态逻辑继续工作。
